> 默认脚踏已迁移至 STM32F103C8T6。当前目标的分层、接线、构建、测试和移植规则见 [STM32 脚踏指南](STM32_PEDAL.md)。下文 ESP32 脚踏内容仅适用于保留的旧后端。

后续实现必须维护 [HAL 边界](HAL_PORTING.md)：`gg_core/gg_app` 不得 include 平台 SDK、RTOS、驱动或板级配置；硬件访问仅通过 `gg_hal_t`，平台文件放入 `firmware/platform/<平台>`。新增能力先完善标准 C 契约，再实现后端。每次改动同时运行无 SDK 的完整应用测试与对应平台构建。

先读 ARCHITECTURE.md，再读当前源码和两个 DESIGN.md。架构文档是目标，不是已实现事实。不得直接将待办改为完成。不得顺带更换引脚、USB 标识、硬件平台或加入新产品功能。

## 分阶段实施

1. 建立纯 C 主机测试入口和参数检查；从 main 提取 controller、calibration、hid_output。保持两个工程及 HID/JTAG 均可构建。
2. 实现新样本/时间戳接口和超期重同步；明确数据就绪清除语义、无效数据处理、驱动恢复的非阻塞阶段及资源释放。
3. 实现窗口校准、失败保留 bias、默认关闭自动跟踪；落实线性算法和按 dt 滤波。
4. 实现状态机、clutch 和组合手势；校准/故障期间保证实体按键可用。
5. 实现有界快照 FIFO、传输完成事件、断线/挂起恢复、溢出及在途超时策略，并复用到脚踏。
6. 完成统计、四种构建、硬件测试记录，再更新当前实现状态。

每阶段交付代码、相关测试、执行命令和结果。不得把复制算法到另一种语言的复算当成生产 C 代码测试。测试通过后再继续依赖该模块的阶段。工具链阻塞时可完成独立工作，但必须列明未验证部分。

## 必须覆盖的离线用例

| 用例 | 验收条件 |
|---|---|
| 静置校准与噪声超限 | 合格窗口提交一次；不合格保留旧 bias，初次失败禁止运动 |
| 均值超限、缺样及间隔超限 | 分别返回失败原因，不应用部分结果 |
| 低速匀速输入 | 无按键时 bias 不变，死区为零时持续累积计数 |
| 恒速积分 | 滤波进入稳态后，累计计数与解析结果误差不超过一个计数 |
| 非均匀 dt | 在合法间隔内按真实时间积分；非法间隔丢弃并重新建立基准 |
| 重复/无新样本 | 不推进校准、滤波及位移 |
| clutch | 按住转动零输出，释放不回放余量、滤波历史或待发运动 |
| 手势冲突 | 组合手势不切档、不重复校准；单键长按不单样本重置 |
| USB 忙期间按下再释放 | 容量内最终收到有序按下、释放，不合并丢失 |
| 提交失败/完成失败 | 按键保留顺序重试，位移不重复 |
| FIFO 溢出/回调通知溢出 | 有计数，执行全释放与最新状态恢复，无越界或永久卡键 |
| 在途超时 | 结束旧会话并恢复，旧完成事件不能消费新队列 |
| 断线/挂起期间操作 | 恢复只同步当前状态，无旧动作或位移回放 |
| IMU 故障 | 20 ms 后停止运动，按键正常；重初始化后重新校准 |
| 脚踏组合 | W+A、W+S、A+D 及全部释放均准确输出 |

使用可控时钟、模拟 IMU 与 USB ready/submit/complete 事件驱动实际纯 C 模块。覆盖至少一次队列环绕及边界容量。硬件测试另外验证真实事件顺序、轴符号、枚举、采样间隔和端到端延迟。

## 交接提示词
